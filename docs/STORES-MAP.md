### 2.3 Route-resolution rule (THE canonical rule — fb-134)

1. **`stateDir` is RELATIVE** — `packages/dshd-core/cordis.patch.yml:43`
   (`stateDir: .deepartments`), mirrored in
   `packages/dshd-core-min/cordis.patch.yml:27` and the bundle row
   `cordis.patch.yml:7` (parity lock = `test/org-config-parity.test.js`; the
   comment: "The org stateDir — MUST match dsh-deepartments' config.stateDir").
2. **It resolves against the daemon CWD** — every dsh unit puts
   `WorkingDirectory=/` (`dsh.service` stable, `dsh-deepartments-dev.service`
   dev, `dsh-vanilla.service`) → **EFFECTIVE stateDir = `/.deepartments`**.
   Any OTHER cwd (CLI/headless smoke run from `/root` or the repo, pre-flight)
   resolves the SAME relative name to a DIFFERENT tree (the fb-134 class).
3. **The ONLY way to separate stores is a per-unit CWD change** — the value of
   `stateDir` never changes (parity intact); a store separation = drop-in
   systemd `WorkingDirectory=<base>/<profile>` per unit (design §6 F1,
   OWNER-GATED). All writers take `<stateDir>` as an argument and resolve
   against it — 0 formatting/R6 impact.
4. **Hardening (F2, in-repo):** a `.store-profile` marker claims the store on
   first open (mismatch → warn + health-alert, non-destructive), store-file
   reads report STALE state when the file is older than the staleness window
   (M1 pattern), and the daemon boot flags ghost-store trees (parallel trees
   carrying `boot-crash.json` / `capacity-gate-state.json`) as a health-alert
   ADVERTENCIA. None of this changes the resolution rule above.
